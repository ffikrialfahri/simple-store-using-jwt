Relasi Antar Tabel.

1.User <-> Role (ManyToMany): Seorang pengguna bisa memiliki satu atau lebih peran (misalnya, seseorang bisa jadi STAFF dan juga CUSTOMER jika sistem memungkinkan, atau ADMIN bisa punya semua peran). Tabel junction t_user_role digunakan untuk menghubungkan m_user dan m_role.
2. User <-> Customer (OneToOne): Satu akun User bisa terhubung ke tepat satu profil Customer. user_id di tabel m_customer adalah foreign key unik yang merujuk ke id di m_user.
3. User <-> Staff (OneToOne): Sama seperti Customer, satu akun User bisa terhubung ke tepat satu profil Staff.
4. Customer -> Transaction (OneToMany): Satu Customer bisa memiliki banyak Transaction. customer_id di t_transaction adalah foreign key ke m_customer.
5. Staff -> Transaction (OneToMany): Satu Staff bisa membuat banyak Transaction. staff_id di t_transaction adalah foreign key ke m_staff.
6. Transaction -> TransactionDetail (OneToMany): Satu Transaction terdiri dari banyak TransactionDetail (item barang). transaction_id di t_transaction_detail adalah foreign key ke t_transaction. Relasi ini menggunakan CascadeType.ALL agar detail ikut tersimpan/terhapus saat transaksi diubah.
TransactionDetail -> Product (ManyToOne): Setiap TransactionDetail merujuk pada satu Product yang dibeli. product_id di t_transaction_detail adalah foreign key ke m_product.
7. Product <-> Tax (ManyToMany): Satu Product bisa memiliki beberapa Tax (misal PPN, PPh), dan satu jenis Tax bisa berlaku untuk banyak Product. Tabel junction t_product_tax digunakan untuk menghubungkannya.

Alur Kerja Aplikasi:
User:
1. API to perform CRUD operations on user data. Implement 3 roles, admin, staff, customer. Admin can do anything. Staff can modify their own profile, create new transactions, and generate reports.
2. Customer can login and update his/her own profile.
3. Customer can download his/her transactions report.
4. Customer can only see his/her transactions in report.
5. Users (admin, staff, customers) can login with either username or email.

Customer:
1. API to perform CRUD operations on customer data. Staff will register customers manually via this API.
2. Customer consists of name, birthdate, birthplace, created_by, created_at, updated_at, and updated_by. Two different customers can share the same name, birthdate, and birthplace.

Products:
1. API to perform CRUD operations on product data.
2. Products consist of name and price at minimum. Price is tax-excluded.
3. Each product has tax. Each product may have multiple taxes, or no taxes at all.

Transactions (with Transaction Details  table/service/repositories ):
1. API to perform CRUD operations on transaction data.
2. Transaction consists of customer, net amount paid (diluar pajak), total amount paid, total tax paid, transaction time, payment status (paid, not paid, cancelled) and payment method.
3. API to query transactions based on these filters:
a. Filter by date range
b. Filter by customer (compare using customer name)
c. Filter by payment status (can be all, single status, or multiple statuses at once)
d. Filter by payment method (can be all, single method, or multiple methods at once)
e. Can choose whether to sort based on transaction time oldest or newest first.
f. Filter by the staff who creates the transaction.

4. API to generate transaction reports:
a. Total amount of money (total amount paid) spent by customer between two dates.
b. Total amount of money (total amount paid) spent by customer throughout the transaction history.
c. Total amount of money (all time) spent per product. (kaya group by product terus aggregate sum total, total amount paid)
